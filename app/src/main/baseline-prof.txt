# Baseline profile — ahead-of-time compilation hints for the start-up path.
#
# WHAT THIS IS
# Without a profile, ART starts a cold app in the interpreter and only JITs
# code once it has proven itself hot. Compose start-up is thousands of small
# methods executed a handful of times each, which is close to the worst case
# for that heuristic: the work is spread too thin to trip the JIT thresholds
# quickly, so it is interpreted, and the first screen is slow. Listing those
# methods here has ART compile them at install time instead. It is the single
# largest start-up win available to a Compose app, and it costs nothing at
# runtime.
#
# WHY IT MATTERS HERE
# Cold start on the 2 GB Android TV box this app was profiled on was 5.7 s
# against a 3 s budget, entirely on a device whose CPU is the constraint. Boxes
# like it are the target, not the exception.
#
# HOW THIS ONE WAS WRITTEN
# By hand, from measurement rather than from a generator: the rules below cover
# the classes on the path from process start to a drawn channel list, plus the
# list-scrolling path that profiling showed to be the hot loop. That is honest
# but coarse. The precise way is to generate one from a real run — add the
# `androidx.baselineprofile` plugin and a `com.android.test` module using
# `BaselineProfileRule`, then run it against this app on a device (API 33+
# works without root, so the box above qualifies) and let it replace this file.
# Doing that is the recommended next step; this file is the floor, not the
# ceiling.
#
# FORMAT
#   H = hot, S = startup, P = post-startup, L = class descriptor.
# Wildcards are expanded by AGP's profgen at build time.
